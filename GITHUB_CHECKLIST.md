# Действия в GitHub, требующие аккаунта

Выполняйте пункты после создания репозитория на GitHub.

## 1. Создать удалённый репозиторий
1. Войдите в GitHub и нажмите **New repository**.
2. Название: `git-docker-practice`.
3. Выберите Public или Private по указанию преподавателя.
4. Не добавляйте README, `.gitignore` и License (они уже есть локально).
5. Создайте репозиторий.

## 2. Связать и отправить локальный репозиторий
В терминале из каталога проекта выполните, заменив `ВАШ_ЛОГИН`:
```bash
git remote add origin https://github.com/ВАШ_ЛОГИН/git-docker-practice.git
git push -u origin main
git push -u origin feature/github-review
```

## 3. Изменить README через веб-интерфейс
Откройте `README.md` на GitHub → Edit (карандаш) → добавьте в конец строку:
`Изменение внесено через веб-интерфейс GitHub.`
Сохраните через **Commit changes** в `main` (если защита ветки уже включена — делайте через отдельную ветку и PR).

Затем локально получите изменение:
```bash
git pull --rebase origin main
```

## 4. Pull Request и Code Review
1. На GitHub откройте **Pull requests → New pull request**.
2. Base: `main`; compare: `feature/github-review`.
3. Вставьте описание: «Добавлен раздел с инструкциями по проверке проекта и использованию Docker».
4. Создайте PR.
5. Оставьте содержательный комментарий в Conversation или Files changed, например: «Проверил README: команды запуска соответствуют конфигурации Docker Compose».
6. Нажмите **Merge pull request**, подтвердите слияние.
7. Удалите feature-ветку кнопкой **Delete branch**.
8. Локально обновите `main`:
```bash
git checkout main
git pull origin main
```

## 5. Доступы и защита ветки
Для проверки пункта о правах доступа нужен второй GitHub-аккаунт (например, аккаунт одногруппника).
1. Settings → Collaborators (или Collaborators and teams) → Add people.
2. Пригласите пользователя с ролью Write и подтвердите, что приглашение принято.
3. Settings → Rules → Rulesets (или Branches → Add branch protection rule, интерфейс может отличаться).
4. Создайте правило для `main`, включите запрет прямого изменения / Require a pull request before merging. Если преподаватель требует именно запрет прямого push, включите соответствующий параметр ограничения.
5. Проверьте, что прямое изменение `main` блокируется, а изменение через PR разрешено.
6. После проверки удалите приглашённого пользователя в настройках Collaborators.

## Скриншоты для отчёта
Сохраните реальные скриншоты:
- страница репозитория с файлами;
- список коммитов;
- Pull Request с комментарием и статусом Merged;
- настройки Collaborators (приглашение Write);
- правило защиты `main`;
- при возможности — сообщение об отказе прямого push.

Не вставляйте в отчёт фиктивные скриншоты: их необходимо получить в своём аккаунте.
